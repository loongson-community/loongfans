本文包括龙架构过去一周（截至 UTC+8 时间 2026 年 10 月 25 日）的上游社区动向，包括 Linux 内核、编程语言工具链、模拟器及其他项目的移植、优化、平台支持、问题修复和报告等。

本期上游社区动向中的主要亮点有：

- LWJGL 龙架构移植在上游及下游社区均有进展
- 用于 Windows 的龙架构交叉工具链发布
- oneDAL 数据分析与机器学习加速库收到龙架构支持补丁

> 编者按：本周末，我们还会发布对 loong64 社区核心贡献者吴小白及 Elysia 的访谈，敬请期待！

## Java 游戏库 LWJGL 龙架构移植：上下游支持同步推进

玩过《我的世界》(Minecraft) 的朋友可能听说过 LWGJL 这个名字——LWJGL，全称 LightWeight Java Game Library（轻量 Java 游戏库），是 Minecraft 等 Java 游戏常用的图形渲染库；而一直以来，在龙架构设备上游玩 Minecraft 的主要阻碍就是 LWJGL 二进制的缺失。

![在龙芯上运行《我的世界 (Minecraft)》（图：OvOla2）](/images/news/upstream/20261025-lwjgl-on-loongarch-loong64.jpg)

早在 2025 年，社区开发者 Catty Steve (Catty2014) [便提交过龙架构支持补丁](https://github.com/LWJGL/lwjgl3/pull/1068)，并辨认了数个依赖项目中缺漏的修复。而到今年九月开始，Catty2014 推动的部分依赖库修复或支持补全，如 [Base X-platform Library (bx)](https://github.com/bkaradzic/bx) 及 KhronosGroup 的素材处理库及工具 [KTX-Software](https://github.com/KhronosGroup/KTX-Software/pull/1249) 均已开始接受龙架构支持补丁（后者有测试设备需求，待对接）。

![HMCL 是龙架构社区用户游玩 Minecraft 的常用途径（图：Hello Minecraft! Launcher 主页）](/images/news/upstream/20261025-hmcl-interface.webp)

下游社区及应用程序也有行动，如 [HMCL 启动器 (Hello Minecraft! Launcher)](https://hmcl.huangyuhui.net/) 先前已自行构建并实现了随游戏下载龙架构 LWJGL 二进制的功能，而近期 loong64 社区开发者 OvOla2 及吴小白也[协作实现了 CI 发布流程](https://github.com/loong64/lwjgl3/commit/7cf69fa61e734fa1a6d29f3bfab22e9df64928f6)，可跟随上游同步构建和发布龙架构二进制，方便有需求的用户。

LWJGL 上游的龙架构支持能否最终实现，让我们拭目以待。

## loong64 社区发布用于 Windows 的龙架构交叉编译器

![在 Windows 构建龙架构二进制](/images/news/upstream/20261025-loongarch64-cross-on-windows.png)

Elysia-best 为 loong64 社区维护的交叉工具链项目 cross-tools [新增了供 Windows 使用的龙架构交叉编译器](https://github.com/loong64/cross-tools/commit/47103ab157b7a0a349af9930c7d6b8511ea818bb)，有需要的开发者朋友可通过 [Github 仓库](https://github.com/loong64/cross-tools/releases/tag/20261022)下载工具链。

## oneDAL 数据分析与机器学习加速库收到龙架构支持补丁

上周，Gleb Popov 向 UXL Foundation 维护的 oneAPI Data Analysis Library（oneAPI 数据分析库）[提交了龙架构的初步支持](https://github.com/uxlfoundation/oneDAL/pull/3902)，使其可在龙架构上构建；该补丁正由项目维护者审阅。UXL Foundation 是由 Intel 发起的跨厂商、跨架构加速器编程架构。

目前，项目维护者提出需要龙架构设备以便支持其 CI 测试工作。爱好者社区工作人员正与其联系洽谈相关事宜。

## ELF 工具集 (elfutils) 收到龙架构 eu-stackprof 剖析器移植

日前，ELF 工具集 elfutils 发布 0.196 版，新增了基于程序调用栈的性能剖析工具 `eu-stackprof`，对接 Linux 内核的 `perf_event` 机制，可对全系统级别和特定进程树采样，供剖析器使用。社区开发者 Xuerui Wang 随后[提交了 `eu-stackprof` 的龙架构移植补丁](https://sourceware.org/pipermail/elfutils-devel/2026q4/009792.html)，相信在未来一个版本发布后，各位可以利用这一新工具剖析龙架构二进制性能了。

## GNU 工具链：本周维护进展

本周 GNU 工具链方面的工作以日常修补为主。

### GNU 编译器集合 (GCC)

近期 GCC 增加了一项架构无关优化：在已知按位或操作的两输入没有共同的为 1 的位的情况下，用加法操作替代这一按位或操作。这有助于利用龙架构的 `alsl` 或者 x86 的 `lea` 之类的指令，但不幸的是龙架构后端中利用 `bstrins`、`bytepick` 指令的优化因未能匹配使用加法操作代替按位或操作后的中间代码而失效。Xi Ruoyao [提交了针对上述优化的修复补丁](https://gcc.gnu.org/pipermail/gcc-patches/2026-October/735788.html)。

### GNU C 库 (glibc)

Deng Jianbo [提交了为龙架构的 `sysconf` 函数增加通过 `cpucfg` 指令获取缓存相关信息的功能的补丁](https://sourceware.org/pipermail/libc-alpha/2026-October/181328.html)。该功能预计有助于应用程序通过架构无关的 API 获取缓存信息，从而降低移植所需的人力。

Adhemerval Zanella [提交了为龙架构的 `fpu_control.h` 增加 `__BEGIN_DECLS`/`__END_DECLS` 宏的补丁](https://sourceware.org/pipermail/libc-alpha/2026-October/181411.html)，以修复 `__loongarch_fpu_setcw` 和 `__loongarch_fpu_getcw` 从 C++ 代码调用时被不正确地 mangle 的问题。这是在一次针对缺失 `__BEGIN_DECLS`/`__END_DECLS` 问题的全面排查中发现的，未发现实际受影响的下游项目（无论如何，在编写代码时，最好使用可移植的 `fegetenv`/`fesetenv` 函数而不是架构专有的函数）。

### Binutils

Zhao Zhou [删除了汇编器 (GNU as) 对不存在的 `xvhseli.d` 指令的“支持”](https://sourceware.org/cgit/binutils-gdb/commit/?id=214080ae5328425c3395a116e45d3e4c26f29515)，但编辑组并不是很清楚之前为什么会存在汇编不存在的指令的逻辑。此外，他还[提交了补丁](https://inbox.sourceware.org/binutils/20261021015156.65492-1-zhaozhou@loongson.cn/)，为汇编器 (as) 防止将处理超过范围的条件跳转指令的逻辑（例如，将 `beq a0, a1, foo` 改写成 `bne a0, a1, 4; b foo`）错误地作用于带 `R_LARCH_B16` 重定位的 `jirl` 指令——实际代码中大概不会存在此种 `jirl` 指令。
