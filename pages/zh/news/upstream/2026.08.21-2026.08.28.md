本文包括龙架构近一周（截至 UTC+8 时间 2026 年 8 月 28 日 18:00）的龙架构上游社区动向，包括 Linux 内核、编程语言工具链、模拟器及其他项目的移植、优化、平台支持、问题修复和报告等。

本期上游社区动向中的主要亮点有：

- Perf 工具收到一系列断点功能修复
- LLVM BOLT 龙架构支持正开始筹备、反汇编器收到初始语法高亮支持
- C/C++ 包管理 Canon 合入龙架构的初始支持
- SIMD/向量编程库 Highway 合入龙架构 LSX/LASX 优化的 `CeilInt`/`FloorInt` 实现

## Linux 内核

本期 Linux 内核动态集中在针对现有功能和行为的修正上。

### 平台支持

两周前，Huacai Chen 提交了针对多路服务器上 CPU 调频调压驱动的行为问题修复。本周该补丁已[翻新到了](https://lore.kernel.org/loongarch/20260828031201.1500767-1-chenhuacai@loongson.cn/)第二版，修复了第一版补丁集审阅过程中发现的 `loongson3_cpufreq_get()` 的返回值错误的问题，改用 `nid_to_addrbase()` 获取处理器节点基址（而非硬编码），解决未开启 `CONFIG_SMP` 的配置下的编译修复，并订正一系列错字、添加 `Fixes:` 标签以便修复后续自动回合到活跃稳定及长期支持 (longterm) 分支。

### KVM 子系统

Chi Zeng [提交了](https://lore.kernel.org/loongarch/20260828093604.56622-1-zeng_chi911@163.com/)针对 EIOINTC 可能收到超出 MSI 数据大小限制（256 位）的数据包，进而导致越界读写内核内存段和内存数据损坏的修复。本周他还[提交了](https://lore.kernel.org/loongarch/20260828094825.357630-1-zeng_chi911@163.com/)一笔针对 KVM 虚拟化内存“槽”/段行为的修改，仅在 `KVM_MR_FLAGS_ONLY` 标记被选中时迁移虚拟内存槽的架构标识（如 `KVM_MEM_HUGEPAGE_CAPABLE` 或 `KVM_MEM_HUGEPAGE_INCAPABLE`），目前该补丁修改的原因和具体效果尚不明确，有待子系统维护者审阅。

### BPF 子系统

Kumar Kartikeya Dwivedi [提交了](https://lore.kernel.org/loongarch/a5d4c26c-6735-8af1-1d3f-fe7f1898b285@loongson.cn/)针对龙架构 BPF JIT 后端 indirect trampoline 栈参数错误的修复补丁。Tiezhu Yang 已提供审阅意见，有待进一步修订。

Tiezhu Yang [提交了](https://lore.kernel.org/loongarch/20260828075100.24776-1-yangtiezhu@loongson.cn/)针对 `insn_is_cast_user()` 函数分支偏移值量计算逻辑中一处差一错误的修复。

### 其他代码清理及修复

Wentao Guan [提交了](https://lore.kernel.org/loongarch/20260825014806.3926864-1-guanwentao@uniontech.com/)修复龙架构 Return Hook Trampoline 代码中错误恢复了用于存储每核心 (`percpu`) 基址的 `$r21` 寄存器，导致 I/O 负载高时使用 `kretprobe` 可能出现错误 RCU 警告的补丁。

Anthony Iliopoulos [提交了](https://lore.kernel.org/loongarch/20260820124933.144476-1-ailiop@suse.com/)删除龙架构对称多处理 (SMP, Symmetric Multi-Processing) 代码 (`arch/loongarch/kernel/smp.c`) 中未使用的 `setup_profiling_timer()` 函数的补丁，并清理相关头文件引用。

Jérémy Jean [提交了](https://lore.kernel.org/loongarch/20260823211822.2181816-2-Jeremy.Jean@oss.cyber.gouv.fr/)一笔针对 kprobes 未正确检查运行状态，可能导致抢占引用计数下溢 (preempt count underflow) 的修复。

Fangxu Li [提交了](https://lore.kernel.org/loongarch/20260821032702.4258-1-lifangxu22@gmail.com/)针对 Perf 工具未定义龙架构 Rust 目标平台 (`loongarch64-unknown-linux-gnu`) 导致构建失败的修复。随后 Rui Wang 指出，他先前在四月已经[提交了](https://lore.kernel.org/loongarch/20260414080500.320095-1-r@hev.cc/)修复，但该笔修复在得到了多名维护者确认的情况下仍未合并，可能是上游疏忽。

Tiezhu Yang [提交了](https://lore.kernel.org/loongarch/20260826110306.6847-1-yangtiezhu@loongson.cn/)一系列针对 Perf 工具断点功能的问题修复。

### 问题报告与英雄帖

Shyliuli 向智谱 (Z.ai) 的氛围编程工具 ZCode [提交了](https://github.com/zai-org/feedback/issues/381)新增龙架构支持的请求。Shyliuli 表示，龙架构社区已有维护针对 ZCode 所使用的 Electron 开发环境及运行时的支持，官方可考虑构建并发布龙架构安装包。

### 移植、优化与修复进展

Chris-wh233 为 C/C++ 包管理 Conan [新增了](https://github.com/conan-io/conan/pull/20288)龙架构主机探测及架构配置信息，是为该包管理新增龙架构支持的第一步。该修改已合入上游。

Iacob 向跨平台 Java 串口设备通讯库 jSerialComm [提交了](https://github.com/Fazecast/jSerialComm/pull/635)龙架构的 Java 本地接口 (JNI, Java Native Interface) 支持。补丁待上游审阅。

manchangfengxu 向 Google 的 Linux 内核模糊测试工具 (fuzzer) syzkaller [提交了](https://github.com/google/syzkaller/pull/7813)基础龙架构 KVM/SYZOS 支持，可实现自动化虚拟机创建、探测和退出追踪功能；作者表示后续还将提交扩展 SYZOS 命令、IRQ/设备调试、多 vCPU 及计时器等功能的支持。该笔修改已经过多轮 AI 辅助审阅和修订，有待维护者进一步审阅。

Ravi (RaviTriv) 为 Google 的 SIMD/向量编程库 Highway [新增了](https://github.com/google/highway/pull/3324)基于 LSX/LASX 的 `CeilInt`/`FloorInt` 实现。该修改已合入上游。

wszqkzqk 向 Rust 的 Linux 用户空间 API 绑定库 linux-raw-sys [提交了](https://github.com/sunfishcode/linux-raw-sys/pull/195)龙架构的 `FIEMAP` ioctl 定义。上游一名贡献者审阅后，建议 wszqkzqk 同时修改生成器代码 (`src/loongarch64/ioctl.rs`)。

Xi Ruoyao [修复了](https://skia-review.googlesource.com/c/skcms/+/1203676) skcms 在使用 GCC 构建时因代码中使用 `[[clang::musttail]]` 强制尾调用接受向量参数的函数，导致在调用惯例不使用向量寄存器传参的平台上（如龙架构）构建失败的问题。

Zoinen 为双面板文件管理器 f4 [新增了](https://github.com/unxed/f4/pull/669)包括龙架构在内多个架构的二进制构建与发布支持。该修改已合入上游，预计下一个版本发布时将附带龙架构二进制。他还为 Go 语言 TUI 界面库 vtui [添加了](https://github.com/unxed/vtui/pull/72)龙架构二进制构建与发布流程，也已被上游合并。
