This article contains LoongArch upstream community activities in the past week (as of July 31st 2026 18:00 CST), including ports, optimization, platform support, bug fixes and reports, etc. in Linux kernel, compiler toolchains, emulators and other projects.

Key upstream community activities:

- The release manager of glibc 2.44, Andreas K. Huettel, stated that the test results for LoongArch are at the "Perfect" level, just like those for x86 and ARM.
- Improvements to Loongson 3B6000M platform support
  - WeMeet successfully runs on 3B6000M via liblasx2lsx
  - Fixed the backlight power state loss after resuming from S3 (sleep) on some 3B6000M laptops
  - Fix for touchpad cursor stuttering and lagging on some 3B6000M laptops is in progress
- LAT received the fix for Steam and the CEF sandbox support, pending verification

This week's activities in the Linux kernel focus on platform functionality fixes and enhancements (laptops, EDaC, and security engine). The KVM subsystem received a fix for a program counter (PC) double advance.

### Platform Support

Zixing Liu [submitted](https://lore.kernel.org/loongarch/20260722044457.1333404-1-liushuyu@aosc.io/) a patch to workaround the backlight power state loss on the EAECIS NL60R laptop (Loongson 3B6000M) after resuming from S3 (sleep). This issue is reproducible on EC firmware version 1.11, but irreproducible on EC firmware version 1.9. The Linux mainline has merged the patch.

Qunqin Zhao [submitted](https://lore.kernel.org/loongarch/20260730063035.230686-1-zhaoqunqin@loongson.cn/) a patch to encode node and memory controller information into EDAC information using the ACPI \_DSD property `mc-idx`. This improves the accuracy of EDAC information output.

Qunqin Zhao [submitted](https://lore.kernel.org/loongarch/20260730082608.1929-1-zhaoqunqin@loongson.cn/) the 5th revision of the patch to fix the multi-node support for Loongson SE (Security Engine). This revision mainly addressed the feedback from Sashiko AI.

### KVM Subsystem

Chi Zeng [submitted](https://lore.kernel.org/loongarch/20260723111552.1623996-1-zeng_chi911@163.com/) the fix for a program counter (PC) double advance in a MMIO (Memory-Mapped IO) read path in the KVM subsystem. Bibo Mao [stated](https://lore.kernel.org/loongarch/c7d6c9ab-9df2-89fc-0a2e-1389b6f5d3ed@loongson.cn/) that the issue could potentially cause critical failure, and approved the patch.

Bibo Mao [submitted](https://lore.kernel.org/loongarch/20260727072109.2151675-1-maobibo@loongson.cn/) a patch to add support for multiple VMID (virtual machine ID) to the LoongArch KVM subsystem.

### BPF Subsystem

Lehui Pu [fixed](https://lore.kernel.org/bpf/20260722112754.1615201-3-pulehui@huaweicloud.com/) a memory leak in the `bpf_jit_free()` function of the LoongArch BPF subsystem. Huacai Chen has merged the patch.

Chenguang Zhao [submitted](https://lore.kernel.org/loongarch/20260729022837.355549-1-chenguang.zhao@linux.dev/) the inline support for the new kernel pointer exchange function (`bpf_kptr_xchg()`) in the LoongArch BPF subsystem, which improves the performance.

### glibc

<!-- https://sourceware.org/git/gitweb.cgi?p=glibc.git](https://sourceware.org/git/gitweb.cgi?p=glibc.git -->

The release manager of glibc 2.44, Andreas K. Huettel, [stated](https://sourceware.org/pipermail/libc-alpha/2026-July/179166.html) that the test results for LoongArch are to be considered "Perfect", just like x86 and ARM.

After 2.44 is released, Xi Ruoyao analyzed and [reported](https://sourceware.org/pipermail/libc-alpha/2026-July/179161.html) that the interaction between the newly added `posix_spawn_file_actions_chdir` alias and gnulib results in a infinite recursion by calling the aliased `posix_spawn_file_actions_chdir_np` function:

- The issue is essentially architecture-independent. We post it here to solely facilicate LoongArch distribution maintenance.
  - Known affected software packages include m4, Gettext, Bison and wget2. Distributions would need to **work around** the issue when rebuilding these packages after the glibc update, otherwise the tests run during the packaging process will never terminate, or the binary packages distributed will stuck in some specific cases.
- It is possible to re-bootstrap these packages from the Git repository to fetch the latest gnulib with the fix for the issue.
- Or, a workaround can be applied by passing `ac_cv_func_posix_spawn_file_actions_addchdir=yes` and `ac_cv_func_posix_spawn_file_actions_addfchdir=yes` arguments to the configure script.

## Emulators

This week's activities in emulators focus primarily on routine maintenance. Box64 received multiple optimizations, LAT received the compability patch for Steam and the CEF sandbox, liblasx2lsx fixed WeMeet's compatibility with ABI 2.0 systems.

### Box64

<!-- 刘阳负责；https://github.com/ptitSeb/box64 -->

This week's commits in Box64 are primarily performance optimizations for DynaRec and correctness fixes.

Yang Liu [submitted](https://github.com/ptitSeb/box64/commit/e3cb94f490b37bb8d48a27f9c40c6a87851fd295) the optimization for the implementation of the SHA1 opcode (in collaboration with phorcys) to improve performance.

Yang Liu [submitted](https://github.com/ptitSeb/box64/commit/fd895bd1427040bf89849593fc5e617541ac385d) the optimization for the synchronization overhead of MXCSR rounding mode by caching MXCSR rounding mode in LoongArch's FCSR3 register, and removed the FCSR synchronization code used to be repeatedly called with rounding-related instructions. This change removed unnecessary register reads and writes, reducing the emulation overhead for heavy floating-point loads.

Yang Liu [submitted](https://github.com/ptitSeb/box64/commit/a2ae0500d85f04c2fbf957f4326757a274a04ac8) an extension for the instruction fusion to expand fusion from a single consumer 1+1 pattern to a 1+N pattern, allowing a single instruction to set EFLAGS to fuse with multiple subsequent instructions, and maintained the compatibility of fusing signed and unsigned flags on both sides of the fusion. He subsequently [submitted](https://github.com/ptitSeb/box64/commit/c32ebc76fde5a1a680f50acee2b52b36d3961d28) the fusion for SF flags, integrating signed flags into the native flag calculations for instructions such as TEST. The two changes work together to expand the coverage of the instruction fusion, reducing flag recalculations and issued code length.

Yang Liu [submitted](https://github.com/ptitSeb/box64/commit/588f1d9c932929bb0801cfe9faa91db2f7e150b6) the optimization for the jump safe macro by introducing a distance heuristic that chooses either a direct short jump or a safe jump sequence based on the distance to the target.

The remaining commits are correctness fixes and functionality completions: Yang Liu [submitted](https://github.com/ptitSeb/box64/commit/88f6cb97c7c64296ebc5e0ae318eac865293db2f) the fix for the scratch register shortage in certain VAES opcodes, [submitted](https://github.com/ptitSeb/box64/commit/edc68c032a33487cfb4112356d342f7d352bbfef) the fix for the ARPL opcode regression (introduced in `fd6bdfe6`), [submitted](https://github.com/ptitSeb/box64/commit/df697c683cc7fd4d94a154aebd938aece12fb0c6) the support for the `F0 F6 /2 LOCK NOT` opcode, and [submitted](https://github.com/ptitSeb/box64/commit/d8df33a9cb73214cb955a88af0554cf04c5d3686) the floating-point parameter support for simplewrapper.

### lasx2lsx

Yang Liu [fixed](https://github.com/lat-opensource/liblasx2lsx/pull/6) a segmentation fault when a program creates a new thread and execute LASX instructions in the new thread using lasx2lsx, a software LASX (LoongArch SIMD Extension, a 256-bit vector extension) emulation library. It has been tested by running WeMeet on the 3B6000M platform with `LD_PRELOAD=/usr/lib/liblasx2lsx.so`.

### Issues and Requests for Assistance

Amberer [filed](https://github.com/skyjt/teahouse/issues/20) a ticket requesting LoongArch support in teahouse, an "intranet only, IP-based LAN instant messaging and file transfer tool".

Martin Liška (marxin) [added](https://github.com/wild-linker/wild/pull/2276) a cross-compiling CI container image based on Arch Linux for the Wild linker, and discovered that the image does not support LoongArch as a cross target.

Hecai Yuan [filed](https://github.com/orbbec/OrbbecSDK_v2/issues/178) a ticket requesting LoongArch port and LSX optimization in OrbbecSDK_v2, the Orbbec® 3D camera SDK. The upstream responded that they will assess the feasiblity, but also suggested to contact the sales team to accelerate the process if there is an urgent need.

### Ports, Optimizations, and Fixes

subotac [fixed](https://github.com/bytecodealliance/wasmtime/pull/14030) a lower-bound write overflow in wasmtime, a WASM runtime, by reserving the fiber stack space before saving registers. The patch is pending upstream review.

Hecai Yuan [submitted](https://github.com/OpenMathLib/OpenBLAS/pull/5942) the fix for a segmentation fault that occurs during updates and kernel copying on double-precision real symmetric matrices. The patch is pending upstream review.
