This article contains LoongArch upstream community activities in the past week (as of August 7th 2026 18:00 CST), including ports, optimization, platform support, bug fixes and reports, etc. in Linux kernel, compiler toolchains, emulators and other projects.

## Linux Kernel

<!--

-->

There are not many patch activities in the Linux kernel this week, including the EDAC support and refactors of the current KVM subsystem patches.

### Platform Support

Qunqin Zhao [refactored](https://lore.kernel.org/loongarch/20260805085414.1482-1-zhaoqunqin@loongson.cn/) the patch that adds extra memory controller node information to EDAC messages to the second revision. In addition to code style cleanups, the new revision fixed a compiler warning and a potential division-by-zero error.

### KVM Subsystem

Tao Cui [asked](https://lore.kernel.org/loongarch/7e2648e9-e333-42f7-857a-8337ef033147@linux.dev/) Bibo Mao about the feasibility of introducing the `KVM_CAP_VCPU_EVENTS` macro to LoongArch along with a LoongArch-specific `kvm_vcpu_events` structure, in order to implement a method for quickly capturing the current interrupt and exception migration state. Tao Cui speculated that the `kvm_vcpu_sync_intr()` function [introduced](https://lore.kernel.org/loongarch/20260519094308.3983046-7-maobibo@loongson.cn/) in an earlier KVM patchset by Bibo Mao which served a similar purpose was obsoleted due to implementation difficulties. In response, Bibo Mao [explained](https://lore.kernel.org/loongarch/ca52efd4-5601-2448-b17c-6d73e1002fd7@loongson.cn/) that the patch was removed because the implementation to track interrupts and migration exceptions required further revisions after introducing DMSINTC, and AI reviews reported issues. He also pointed out that introducing a new structure would break userspace compatibility and was therefore unnecessary.

Bibo Mao [refactored](https://lore.kernel.org/loongarch/20260806020739.2149268-1-maobibo@loongson.cn/) the patch that adds multiple VMID (Virtual Machine ID) support to the LoongArch KVM subsystem to the second revision. This version primarily changed the guestid capability detection method (originally using the LVZ version to detect, but since the version does not fully correspond to the feature presence, it was changed to use the 8th bit of CPUCFG8), fixed the CPU bit setting method, and renamed some variable and function names from the previous revision. Huacai Chen provided further review comments, and Bibo Mao will submit a third revision after addressing the feedback.

## Toolchains

<!-- xry111 编撰审阅；工具链合集内容也可参考：https://patchwork.sourceware.org/ -->

This week, the main highlight in toolchains is the initial implementation of Zig's self-hosted backend: Zig currently relies on LLVM as the code generation backend for LoongArch. If it can switch to a self-hosted backend, it will be able to better maintain consistency with upstream's future development plans and reduce maintenance costs.

### Binutils

In response to the "GOT layout corruption" in statically linked binaries with Binutils 2.47 [reported last week](https://sourceware.org/pipermail/binutils/2026-July/150558.html), Xi Ruoyao considered Yanjun Yang's patch to be incorrect (at the very least, the commit message was apparently unreasonable). He constructed test cases targeting the code paths affected by both the PR29655 fix and Yanjun Yang's fix, and discovered that the PR29655 fix exposed a code bug that caused relocations such as R_LARCH_GOT_PC_LO12 to be resolved with a 16-byte offset. He then [proposed](https://sourceware.org/pipermail/binutils/2026-August/150628.html) a fix, and Yanjun Yang subsequently confirmed that this fix indeed resolves the issue.

### GCC

<!-- https://gcc.gnu.org/git/?p=gcc.git -->

Xi Ruoyao [submitted](https://sourceware.org/pipermail/gcc-patches/2026-August/726047.html) a "fix" patch for the mismatching register used by the caller and the callee when passing floating-point arguments in COBOL programs. However, the patch is quite ugly and clearly does not work when LTO is enabled, so he hoped someone could propose a better fix.

In response to the patch that Ben Shi [proposed](https://gcc.gnu.org/pipermail/gcc-patches/2026-July/725925.html) last week to add a split rule for using two bstrins instructions to avoid loading an immediate for certain bitwise AND operations, Jeffery Law suggested using an expand rule instead of a split rule. After Xi Ruoyao tried the expand rule, he found that because LoongArch's cost model considers loading an immediate as having "negligible cost since it can usually be taken out of loops," the combine optimization pass would re-merge the two bstrins instructions generated by the expand rule back into an AND instruction that requires loading an immediate. This reveals a fundamental conflict between the cost model's logic and the logic of this patch, and subsequent benchmark results will be needed to determine which side is correct.

### LLVM

<!-- lrzlin 审阅；https://github.com/llvm/llvm-project -->
heiher [implemented](https://github.com/llvm/llvm-project/pull/214120) patterns that use `VPICKVE2GR_BU/HU` and `[X]VPICKVE2GR_WU` for vector element extraction followed by zero extension, eliminating redundant masking instructions.

Lei Wang [extracted](https://github.com/llvm/llvm-project/pull/213582) `shouldRelaxAlign` from `relaxAlign` and called it during `emitCodeAlignment` to eagerly set the `linker-relaxable` flag on each aligned assembly fragment, ensuring that `isRangeRelaxable` returns correct results before the layout phase.

heiher [implemented](https://github.com/llvm/llvm-project/pull/214204) an optimization that folds the expression `(shl (extract_vector_elt X, I), GRLen - EleBits) ==/!= 0` into `(extract_vector_elt X, I) ==/!= 0` when `GRLen - EleBits` equals the left-shift amount. This exposes `EXTRACT_VECTOR_ELT` to subsequent Combine and allows direct selection as `VPICKVE2GR_*` instructions, eliminating redundant left-shift instructions.

wszqkzqk [fixed](https://github.com/llvm/llvm-project/pull/214621) the conversion from `<4 x float>` to `<4 x i64>` in LASX. The previous pattern truncated float values outside the representable range of `i32/u32`. He modified it to use `XVFTINTRZL.L.S` for signed conversions and combined `XVFCVTL_D_S` with `XVFTINTRZ.LU.D` for unsigned conversions to avoid truncation.

## Emulators

This week's activities in emulators primarily focus on compatibility fixes. Box64 started to implement support for non-4KiB page sizes, and LAT began improving user-level runtime environment management.

### Box64

<!-- 刘阳负责；https://github.com/ptitSeb/box64 -->

This week's Box64 commits mainly focused on 4K page size emulation and compatibility improvements for the ELF loader, as well as DynaRec performance optimizations and correctness fixes, and released v0.4.4.

ptitSeb [released](https://github.com/ptitSeb/box64/commit/2f130fab1d6e1a4ee8a71dc60cfdfcc839ad192a) v0.4.4. This version brings a lot of refactors and speed improvements to the LoongArch backend, and includes a new graphical configuration tool, DynaCache enabled by default, and various other improvements.

This week's main progress is 4K page emulation on non-4K page hosts (e.g., 16K page systems). Yang Liu [submitted](https://github.com/ptitSeb/box64/commit/1b79a0c060f18bda82d8b2c602f6b20a5cf1434d) an implementation of 4K page size emulation to improve compatibility; [submitted](https://github.com/ptitSeb/box64/commit/5656decbdecc5fa2cc0fbad8335a2fbe72689974) a fix for 4K mmap canary page handling; [submitted](https://github.com/ptitSeb/box64/commit/9c11c5671c6d385357321856ff75894afab4ee5f) a madvise wrapper on non-4K page systems (MADV_DONTNEED falls back to memset on unaligned cases, and also handles unaligned mprotect); [submitted](https://github.com/ptitSeb/box64/commit/3c670efe6fe07ce290a1496ce750c064d0c6a052) a fix for wine mappings on 16K page hosts; [submitted](https://github.com/ptitSeb/box64/commit/61d01a4c2c7220b57952b83c270df3f058180095) a fix for Proton support and ported the elfloader to Box32; subsequently [submitted](https://github.com/ptitSeb/box64/commit/491ab0e3047d590134a115caa8c79d22ed8f88c6) fake 4K protection tracking—since Chromium probes the canary page via getrlimit, this change manually tracks 4K page protection status and wraps getrlimit to fake the probe result; and [submitted](https://github.com/ptitSeb/box64/commit/0e9d41ce1544a6337082ca1ab8d4320953646e1b) a relaxation of the 4K emulation check (mmap ignores fd when MAP_ANONYMOUS is present).

In the ELF loader: Yang Liu [submitted](https://github.com/ptitSeb/box64/commit/b5066f8ab472c2d8dd90384d3bfd9835fb222116) a fix for mapping range calculation, using the host page size instead of p_align (it is valid for p_align to be 16K while the host page is 4K, and the original implementation incorrectly expanded the writable segment range); [submitted](https://github.com/ptitSeb/box64/commit/0db8df7757b523e41cf31b6204c47d22b8fb4f08) a fix for overlapping ELF segment reservation handling, addressing a regression introduced by b5066f8a on 16K page systems; [submitted](https://github.com/ptitSeb/box64/commit/b5d45778c437961a3d7042a680acf33d980f05ff) a fix for mapping unaligned segments, mapping directly from the file when vaddr and offset share the same page offset; [submitted](https://github.com/ptitSeb/box64/commit/bae1de053e87384631d2ee1c9bdd4c1edf360d3c) support for read-only semantics after RELRO relocations, avoiding generating unnecessary always_test blocks on 16K page systems; [submitted](https://github.com/ptitSeb/box64/commit/55ed7e9edb3161b0cafc1daad587aaeb5646bfb8) support for the BIND_NOW dynamic tag; and [submitted](https://github.com/ptitSeb/box64/commit/5d881fd59d192d3ca917d4220c1dc7165d7f3ce8) another fix for RELRO relocations. Zane [submitted](https://github.com/ptitSeb/box64/commit/8ef7ef3209169cf30416c1ed1685ea1c9608e67e) a fix for a premature application of GNU RELRO in static binaries.

TLS and signal handling: Yang Liu [submitted](https://github.com/ptitSeb/box64/commit/9cf3ceaa86b40ac04474d0b7e853a70dfec13e34) complete support for CLONE_SETTLS, and [submitted](https://github.com/ptitSeb/box64/commit/5e5e598a6bb2cb5bd932668375103bf882ca0f50) a fix for TLS size adjustment after dlopen; [submitted](https://github.com/ptitSeb/box64/commit/cec0f61e0efeb52477d1b5c3764cecb691f42118) a fix for preserving previous handler, flags, mask, restorer, and alternate-stack state in signal handling, fixing Black Myth: Wukong again (this issue had been partially broken for a long time). Mikura Kyouka [submitted](https://github.com/ptitSeb/box64/commit/fb5294a1252094b407bd26fb62660ffe23569f60) a fix for TF handling when restoring signals by executing one instruction in the interpreter to suppress extra SIGTRAP, fixing Syringe.exe on the Ares extension platform.

DynaRec: Yang Liu [submitted](https://github.com/ptitSeb/box64/commit/e0ae94d742b983c61379c36bf5ebdca1e414957d) a CRC checksum speedup for LoongArch.

The remaining commits are core fixes and feature additions: Yang Liu [submitted](https://github.com/ptitSeb/box64/commit/98459539dcd9192622acde259fa7ebeafdd6826f) a fix for weak symbol resolution order, [submitted](https://github.com/ptitSeb/box64/commit/5ca4b91e00b98092b83ad1ae492d3e621a72ab04) a fix to reset the jumptable entry when adding an alternate, and [submitted](https://github.com/ptitSeb/box64/commit/bc181e78121eef90ced069f957027e5b8301f2c8) a fix for the incorrect fchmodat4 syscall number (434 belongs to pidfd_open since 2019), along with adding more syscalls; [submitted](https://github.com/ptitSeb/box64/commit/15e065ae5dd0207fe4f6cfce565884f68567d64f) wrappers for isoc23_[v]scanf and [submitted](https://github.com/ptitSeb/box64/commit/1058aae5616c98cc7c4ad7f38d6973277b4ff6c6) wrappers for at_quick_exit/quick_exit, [submitted](https://github.com/ptitSeb/box64/commit/ddd3bd602f15da7f51b84b5c4ad89b30b6817e8c) a complete removal of crashhandler handling, [fixed](https://github.com/ptitSeb/box64/commit/fa5fbe6acdfc97607643920ca069f697abe98e59) the eglDebugMessageControlKHR wrapper, and added cs2 and dota2 profiles for Steam, prioritized Steam Runtime libraries, and improved pressure vessel emulation for Protontricks.

### LAT (LoongArch Architecture Translator)

This week, in terms of enhancing user experience, Hanlu Li [added](https://github.com/lat-opensource/lat/pull/365) support for reading x86-64/x86 runtime environments from the user configuration directory. Users can place runtime environments in the specified directories and set the runtime path via command-line arguments ≥ environment variables ≥ user configuration ≥ system configuration ≥ compile-time presets (see the link for detailed usage). As part of this work, she also [added](https://github.com/lat-opensource/lat/pull/370) a runtime environment information query parameter `--runtime-info` to the main program, and [introduced](https://github.com/lat-opensource/lat/pull/369) the LATU runtime installation status monitoring program `latu-runtime-manager`, which can conveniently probe the availability of related components.

In terms of known issue fixes, Hanlu Li [fixed](https://github.com/lat-opensource/lat/pull/371) a lockup when running the `openssl speed` command; YueRengAn [fixed](https://github.com/lat-opensource/lat/pull/363) namespaces not being preserved during `clone()` and `setns()` calls; xiezyang [removed](https://github.com/lat-opensource/lat/pull/377) a useless warning on platforms without LASX (such as Loongson 2K3000/3B6000M) to avoid user confusion.

In terms of code cleanup and maintenance, Hanlu Li [fixed](https://github.com/lat-opensource/lat/pull/375) a build failure with LTO (Link-Time Optimization) enabled; sunhaiyong1978 [removed](https://github.com/lat-opensource/lat/pull/366) the no-longer-used TCG mode binary build scripts, and [fixed](https://github.com/lat-opensource/lat/pull/367) multiple compile-time warnings; Hanlu Li updated the project README file based on the above userspace changes.

### Ports, Optimizations, and Fixes

Xi Ruoyao [fixed](https://github.com/google/highway/commit/13cb08df3ced92df4160c446595f642f30bbd20d) the LASX implementation of NegMulAdd in Highway (the correct implementation requires the multiplication result to not be rounded, and only the final result be rounded, which the previous implementation did not satisfy), resolving the tgamma function test failures when LASX is enabled; and [implemented](https://github.com/google/highway/commit/fe8835e68b21efef111fa2a125c57ae41be8ca69) dynamic LSX/LASX availability probing in Highway when building with GCC 15.3 or later (this allows enabling these instruction features on platforms that support them while maintaining compatibility with platforms that do not).

xm_moe [fixed](https://github.com/ROCm/libhipcxx/pull/28) a build failure on LoongArch in the libhipcxx component of the ROCm framework (a PyTorch-ROCm dependency) caused by an outdated autoconf triggering an "cannot guess system type" error.

Wu Xiaobai (wojiushixiaobai) [added](https://github.com/napi-rs/napi-rs/pull/3442) the LoongArch musl libc build target to napi-rs, a Node.js Rust extension development framework. The pull request is pending upstream review.

Xi Zhang (cheungxi) [added](https://github.com/oxc-project/oxc-resolver/pull/1343) the `loongarch64-unknown-linux-gnu` build target for the N-API distribution of Oxc Resolver, a JavaScript plugin module resolver. The pull request is pending upstream review.

ErnstPeng [added](https://github.com/OpenMathLib/OpenBLAS/pull/5964) small matrix kernel of sgemm_lasx/lsx and dgemm_lsx to OpenBLAS.

Mo Luo (moluopro) [fixed](https://github.com/OpenMathLib/OpenBLAS/pull/5961) the LoongArch CI build for OpenBLAS by replacing the QEMU used in the build process with the version distributed by Ubuntu.

Hecai Yuan (HecaiYuan) [submitted](https://github.com/orbbec/OrbbecSDK_v2/pull/180) a pull request to add LoongArch support to OrbbecSDK_v2, the software development kit for Orbbec's robotic vision products.

lxh (li041) [added](https://github.com/syswonder/hvisor/pull/374) virtualized LoongArch IPI (Inter-Processor Interrupt) support for SMP (Symmetric Multiprocessing) guests in hvisor, a Type-1 bare-metal hypervisor.

nihui [submitted](https://github.com/Tencent/ncnn/pull/6890) a pull request to optimize GEMM (General Matrix Multiplication) weight block quantized int4 for x86, ARM, MIPS, LoongArch, and RISC-V in ncnn, a neural network inference framework.
