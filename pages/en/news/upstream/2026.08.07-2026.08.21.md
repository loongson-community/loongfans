> Due to a scheduling conflict, the editorial team could not publish the last week's upstream activities (August 7th 2026 - August 14th 2026) on time. We sincerely apologize for the delay. This issue is a combined version covering upstream activities from August 7th 2026 to August 21st 2026.

This article contains LoongArch upstream community activities in the past two weeks (as of August 21st 2026 18:00 CST), including ports, optimization, platform support, bug fixes and reports, etc. in Linux kernel, compiler toolchains, emulators and other projects.

Key highlights in this issue of upstream activities:

- The Linux kernel received a fix for the CPU dynamic voltage and frequency scaling support on multiprocessor platforms, the fix also resolves hangs during boot and frequency misreads caused by the dynamic voltage and frequency scaling driver on the Loongson 3B6000 platform
- Zig merged a self-hosted backend for LoongArch, which can speed up compilations and reduce debug difficulties
- Box64 implemented the initial support for 16KiB kernel page size, fixing compatibility issues with *Black Myth: Wukong* and the Linux versions of *Counter Strike 2* and *DOTA 2*
- U-Boot merged a patch to add LoongArch build infrastructure, and the third revision of the platform support patch was submitted

Key highlights in this issue's Linux kernel activities include a platform support fix for the CPU dynamic voltage and frequency scaling, a fix for Zone Devices such as AMD GPU, and a reliability improvement in the KVM subsystem.

### Platform Support

Huacai Chen [submitted](https://lore.kernel.org/loongarch/20260818123921.3600606-1-chenhuacai@loongson.cn/) a fix for the CPU dynamic voltage and frequency scaling behaviour on multi-node servers. According to the test result, the patchset also resolves hangs during boot and frequency misreads caused by the dynamic voltage and frequency scaling driver on the Loongson 3B6000 platform.

Han Gao [fixed](https://lore.kernel.org/loongarch/20260811115749.3465579-1-gaohan@iscas.ac.cn/) an issue in the LoongArch memory management code where the physical address width of page tables was not correctly defined according to the actual hardware conditions (48 bits on 3A5000/3A6000, 47 bits on 3C6000, and 40 bits on the 2K series). The patch fixes an initialization failure in the AMD GPU kernel-mode computing driver, AMDKFD.

George Guo [submitted](https://lore.kernel.org/loongarch/20260807103714.33074-1-dongtai.guo@linux.dev/) the fourth revision of the LoongArch Kexec Handover (KHO) support patchset, continuing to fix code issues identified by reviewers and AI, and merged a build fix.

Hongliang Wang [refactored](https://lore.kernel.org/loongarch/20260817090112.27151-1-wanghongliang@loongson.cn/) the patch that adds clock related properties to the LoongArch I²C bus driver to the 10th revision, fixing a link-time error when `COMPILE_TEST` is enabled on 32-bit architectures. The patch is known to fix touchpad input lagging or stuttering issues on some Loongson 3B6000M laptops.

Qunqin Zhao [refactored](https://lore.kernel.org/loongarch/20260805085414.1482-1-zhaoqunqin@loongson.cn/) the previously submitted patch that adds extra memory controller node information to EDAC messages to the third revision, continuing to fix code and comment issues found during review.

### KVM Subsystem

Tao Cui [submitted](https://lore.kernel.org/loongarch/20260814094738.2552440-1-cui.tao@linux.dev/) a fix for a TOCTOU (Time-of-Check to Time-of-Use) issue in the `pv_feature` variable value assignment of the `kvm_loongarch_cpucfg_set_attr()` function. He refactored the patch to the third revision based on feedback from Huacai Chen and Bibo Mao by the time of this issue's deadline.

### BPF Subsystem

Chaithanya Lagisetty [submitted](https://lore.kernel.org/loongarch/20260817115847.2705791-1-nagachaithanya9911@gmail.com/) a fix for a memory leak in `kvm_loongarch_env_init()`, and [submitted](https://lore.kernel.org/loongarch/20260817123918.2738447-1-nagachaithanya9911@gmail.com/) a fix for a missing `free` operation in the failure path of `kvm_init()`.

George Guo and Tiezhu Yang [submitted](https://lore.kernel.org/loongarch/20260813045306.21571-1-yangtiezhu@loongson.cn/) a patch to add stack walking support to the LoongArch BPF JIT backend.

### Other Code Cleanups and Fixes

Pengpeng Hou [refactored](https://lore.kernel.org/loongarch/20260814075449.14912-1-pengpeng@iscas.ac.cn/) the previously submitted patch that replaces the obsolete `CONFIG_I2C_DESIGNWARE_SLAVE` configuration symbol with `CONFIG_I2C_SLAVE` in the LoongArch default kernel configuration (`defconfig`) to the second revision. This revision mainly also applies the fix to the 32-bit configuration file (`loongarch32_defconfig`).

Bibo Mao [submitted](https://lore.kernel.org/loongarch/20260812040132.113812-1-maobibo@loongson.cn/) a code cleanup patch that removes the obsolete `kvm_arch_flush_remote_tlbs_memslot()` function.

Tiezhu Yang [submitted](https://lore.kernel.org/loongarch/20260813090506.15574-1-yangtiezhu@loongson.cn/) a patch to use `current_stack_pointer` instead of the compiler-specific `__builtin_frame_address(0)` value in the `current_pt_regs()` function. According to Tiezhu Yang, the `current_stack_pointer`-based implementation uses the native `$sp` register and can save up to 16 bytes per stack frame.

Tiezhu Yang [submitted](https://lore.kernel.org/loongarch/20260812032807.15034-1-yangtiezhu@loongson.cn/) a patch to prevent local and mapping symbols from being recorded in `/proc/kallsyms`, allowing tracing tools such as `bpftrace(8)` to resolve accurate kernel stacks on LoongArch.

## Toolchains

<!-- xry111 编撰审阅；工具链合集内容也可参考：https://patchwork.sourceware.org/ -->

In this issue's toolchain activities, aside from routine maintenance work, the main highlight is that Zig merged a self-hosted backend for LoongArch, which can speed up compilations and reduce debug difficulties.

### Binutils

Meng Qinggang [submitted](https://sourceware.org/pipermail/binutils/2026-August/150771.html) a patchset to fix the assembler's (as) handling of expressions that subtract symbol addresses. Previously, the assembler treated the subtracted symbol address as $0$, and this patchset correctly encodes them as relocation records.

Meng Qinggang [submitted](https://sourceware.org/pipermail/binutils/2026-August/150891.html) a patch to avoid the assembler (as) using the `DW_LNS_fixed_advance_pc` DWARF instruction in debug information if possible (i.e., when the region does not contain instructions that could be deleted by linker relaxation), which can reduce the size of debug information for LoongArch (while also reserving an interface for other architectures to utilize this mechanism).

### LLVM

<!-- lrzlin 审阅；https://github.com/llvm/llvm-project -->
heiher [fixed](https://github.com/llvm/llvm-project/pull/216027) an issue [reported](https://github.com/llvm/llvm-project/issues/215935) by Lei Wang where LoongArch DAG instruction selection fails to select LoongArch::BRCOND when its condition is a constant integer, by adding BEQZ/BNEZ patterns as a fallback.

heiher [fixed](https://github.com/llvm/llvm-project/pull/215222) an ABI mismatch with GCC for `_Complex` types of small integers in Clang [reported](https://github.com/llvm/llvm-project/issues/214810) by folkertdev. The patch restricts the complex-type expansion path to floating-point types only, allowing small integer complex aggregates to be packed into a single general-purpose register, consistent with GCC and the la-abi-specs manual.

heiher [implemented](https://github.com/llvm/llvm-project/pull/215520) an optimization that folds selects of the form `select C, (binop X, Y), X` into `binop X, (select C, Y, 0)`, which can shorten the resulting instruction sequence.

heiher [added](https://github.com/llvm/llvm-project/pull/216261) a optimization pass to the LoongArch backend that replaces conditional branches which can be statically evaluated with unconditional branches, inspired by the similar implementation in RISC-V's `RISCVLateBranchOpt` pass.

Runze Lin [added](https://github.com/llvm/llvm-project/pull/217250) an optimization to `eliminateFrameIndex` that places some stack frame offsets into the immediate field of instructions such as `ld/st`, and combines `lu12i.w + add` for materializing high offsets into `PseudoAddUpperImm`, so that the subsequent `MachineLateInstrsCleanup` pass can eliminate redundant higher-bit materializations via CSE. Benchmarks show a 27% performance improvement on the 709.cactus subtest of SPEC CPU2026. The approach is inspired by a [similar optimization](https://github.com/llvm/llvm-project/pull/211748) for RISC-V.

### U-Boot

- The upstream [merged](https://lore.kernel.org/u-boot/178648861345.3127030.13752325250840471153.b4-ty@konsulko.com/) a patch submitted by Yao Zi to add LoongArch support to the CI images

lijunting2020 [submitted](https://github.com/gogf/gf/pull/4847) a dependency update to GoFrame, a Go application development framework, updating the go-sqlite and modernc.org/libc dependencies to enable LoongArch build support. The upstream has merged the pull request.

Mo Luo (moluopro) [fixed](https://github.com/OpenMathLib/OpenBLAS/pull/5973) the initialization failure of the DSDOT (double-precision dot product of two single-precision vectors) accumulator on LoongArch in OpenBLAS.

manchangfengxu [added](https://github.com/google/syzkaller/pull/7784) LoongArch cross-compilation toolchain support to syzkaller, Google's Linux kernel fuzzer. The upstream has merged the pull request.

tangaac [added](https://github.com/rust-lang/cc-rs/pull/1855) the LoongArch 64-bit assembly intermediate layer to cc-rs, a C/C++ to Rust compilation library, achieving basic support for LoongArch in this library.

wszqkzqk [submitted](https://github.com/wild-linker/wild/pull/2411) a pull request to the Wild linker that fixes the `elf/loongarch64/source-info-from-debug/non-lto` and `elf/loongarch64/source-info-from-debug/non-lto` test cases. The upstream has merged the pull request.

Hecai Yuan (HecaiYuan) [submitted](https://github.com/sekrit-twc/zimg/pull/242) LoongArch LSX (128-bit vector instruction set extension) support to zimg, an image processing library. The pull request is pending upstream review.

Xi Zhang [submitted](https://github.com/lovell/sharp-libvips/pull/394) LoongArch build and CI support to libvips-sharp, a .NET binding for the image processing library libvips. The upstream initially said they could not support it because components such as run-on-arch-actions did not yet support LoongArch, but Xi Zhang then indicated that run-on-arch-actions has supported LoongArch since version 3.2.0. The upstream has since provided review comments, and further revisions are pending.
