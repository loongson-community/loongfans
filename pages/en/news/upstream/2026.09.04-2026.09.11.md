This article outlines LoongArch upstream activities in the past week (up to UTC+8 18:00, September 4th, 2026), including ports, optimization, platform support, bug fixes and reports, etc. in Linux kernel, compiler toolchains, emulators, and other projects.

This week's highlights:

- FreeBSD received LoongArch ELF machine type definition, a first step towards upstream support.
- MySQL and Redis databases received a LoongArch hardware timer optimization.
- Mesa received a fix for mistakenly limited vector bidwidths (128-bit vs. 256-bit) on LoongArch, improved performance expected for some drivers.

## Linux Kernel

<!--

-->

There haven't been many new changes to the Linux kernel from the past week, but Tiezhu Yang's discussion and adjustments regarding the implementation of `__smp_mb__before_atomic()` and `__smp_mb__after_atomic()` are likely worth your attention.

### Platform Support

Qunqin Zhao [submitted](https://lore.kernel.org/loongarch/20260911090256.7834-1-zhaoqunqin@163.com/) the 7th revision for his Loongson Security Engine's (SE) multi-node support fixes patchset. Compared to the 5th revision from several weeks ago, Qunqin fixed the interrupt handling logic, the DMA memory size calculation formula, and a few other issues.

### KVM Subsystem

Bibo Mao [submitted](https://lore.kernel.org/loongarch/20260910022118.2339780-1-maobibo@loongson.cn/) the 2nd revision to his previously submitted patch, which sought to fix the `pv_feature` update logic. This revision renamed functions and rebased the changes onto the kernel tree to resolve merge conflicts.

This week, he also [submitted](https://lore.kernel.org/loongarch/20260909083259.1910290-1-maobibo@loongson.cn/) a patch that optimizes the Message Signaled Interrupt injection logic by removing some unnecessary parameter checks.

### BPF Subsystem

Last week, Tiezhu Yang [submitted](https://lore.kernel.org/loongarch/20260902005106.22187-1-yangtiezhu@loongson.cn/) a fix for a CPU soft lockup triggered by the `timer_lockup` test. Tiezhu Yang noted that LoongArch is a weak memory ordering architecture, and the combination of relaxed `atomic_inc()` + `smp_mb__after_atomic()` in the current implementation is insufficient to guarantee the ordering of store and load operations (the latter is not compiled into a hardware data barrier in the current compiler implementation), which contradicts the `bpf_timer_cancel()` function documentation that explicitly states "Need full barrier after relaxed atomic_inc".

This week, he [submitted](https://lore.kernel.org/loongarch/20260902005106.22187-1-yangtiezhu@loongson.cn/) the 2nd revision of the patchset, which changed the approach by removing the architecture-specific `__smp_mb__before_atomic()` and `__smp_mb__after_atomic()` implementations and switching to a generic implementation based on `__smp_mb()`. Tiezhu Yang noted that this implementation correctly issues the hardware DBAR instruction, ensuring the ordering of store and load operations. He also noted that there are many call sites of these two functions in the kernel's filesystem, driver, file management, and network subsystems, all of which may have similar latent issues.

In addition, he [submitted](https://lore.kernel.org/loongarch/20260908073506.29734-1-yangtiezhu@loongson.cn/) the 3rd revision of the BPF `struct_ops` trampoline patchset, which continues to improve code quality.

### Other Code Cleanups and Fixes

Karl Mehltretter [corrected](https://lore.kernel.org/loongarch/20260905091743.41006-1-kmehltretter@gmail.com/) the documentation regarding native `cmpxchg-local` (Local Compare and Exchange) support for LoongArch CPUs. Previously the documentation still listed the LoongArch support as TODO, but in fact the support had existed since LoongArch support entered the mainline kernel in the 5.19 cycle, and was later declared supported in the 7.0 cycle.

This issue's activities in toolchains focus on routine maintenance and fixes.

### Binutils

Xi Ruoyao updated the patch that fixes incorrect resolution of `R_LARCH_GOT_PC_LO12` referring to GNU indirect functions during static linking to the 3rd revision, and Meng Qinggang [merged](https://sourceware.org/cgit/binutils-gdb/commit/?id=8ec22f3191b1917a06dcbe4b6bbef042462bf5b) the patch.

Meng Qinggang [submitted](https://sourceware.org/pipermail/binutils/2026-September/151374.html) a patch to the assembler that deprecates the `-mignore-start-align` flag (this flag prevented the insertion of `NOP` instruction sequences and `R_LARCH_ALIGN` at the start of code sections, but since the assembler can now automatically remove them when not needed, manually specifying the option is no longer needed). It also fixes the failure to mark the corresponding instruction as potentially removable by the linker when explicitly using `.reloc` to encode `R_LARCH_RELAX`, which could lead to alignment errors after linking.

### LLVM

<!-- lrzlin 审阅；https://github.com/llvm/llvm-project -->

> This chapter is compiled with contributions from lrzlin, one of LLVM's LoongArch maintainers.

hazohelet [reported](https://github.com/llvm/llvm-project/issues/222088) that when building specific C code containing the `_Bitint(24)` type with Clang, the compiler may crash when using `#pragma clang loop vectorize_width(4)` to specify the loop vectorization width. Investigation showed that `<4 x i24>` is not a simple type, but a previous lowering optimization for `ISD::SIGN_EXTEND` lacked the relevant check. Lei Wang [fixed](https://github.com/llvm/llvm-project/pull/222250) the issue by allowing the compiler to fall back to the default path for non-simple types.

Rui Wang [prevented](https://github.com/llvm/llvm-project/pull/221714) the Post-RA (Register Allocation) scheduler from scheduling instructions across stack frame register loads/saves in sanitized functions, as such scheduling could prevent the sanitizer from collecting the correct stack frame location when the program crashes.

Lei Wang [added](https://github.com/llvm/llvm-project/pull/222825) some tests for the internal assembler to cover 1/2-byte data relocations, supplementing the previously [introduced](https://github.com/llvm/llvm-project/pull/211754) patch that uses PC-relative relocations when adding or subtracting 4/8-byte symbols.

### LAT (LoongArch Architecture Translator)

<!-- https://github.com/lat-opensource/lat -->

> This chapter is compiled with contributions from "baibaidashixiong", an LAT maintainer.

#### Changes Merged This Week

Wenqiang Wei (ganjue66da) [improved](https://github.com/lat-opensource/lat/pull/416) vector register high-bit analysis, reducing redundant high-bit merging in scalar operations and fixing correctness issues in `POPAW`, 64-bit division, and cross-translation-unit analysis; he also [fixed](https://github.com/lat-opensource/lat/pull/424) residual x87 stack top mappings after non-local jumps, preventing floating-point values from being restored to the wrong position, and [adjusted](https://github.com/lat-opensource/lat/pull/422) the default AOT generation policy to skip generation when the proportion of newly added dynamically translated blocks is less than 5%, reducing repeated cache overhead.

yuerengan (y347812075) [fixed](https://github.com/lat-opensource/lat/pull/419) Chromium sandboxes mistakenly seeing LATX helper threads after switching root: it recognizes pre-saved `/proc` directory descriptors and returns guest thread counts, preventing thread count checks from triggering `INT3`. The author reported that ChatGPT's default sandbox startup had passed the original failure point.

Zhaoyang Xie (xiezyang) [added](https://github.com/lat-opensource/lat/pull/467) a manual PR CI entry point and [simplified](https://github.com/lat-opensource/lat/pull/484) the request parameters, with empty requests defaulting to running the full SPEC2000 test suite.

Hanlu Li (LaurenIsACoder) [added](https://github.com/lat-opensource/lat/pull/444) diagnostic and performance validation guidance, as well as [the requirement to synchronize with upstream](https://github.com/lat-opensource/lat/pull/471).

#### Changes Added This Week

Wenqiang Wei (ganjue66da) continued to [fix](https://github.com/lat-opensource/lat/pull/464) the mutual interference between x87 and SSE rounding states in soft-float mode, synchronizing them separately during state loading and signal return; he also [improved](https://github.com/lat-opensource/lat/pull/425) the guest 4 KiB permission checks on 16 KiB host pages by caching the checks for read/write, cross-page, and atomic operations to prevent protected regions from being bypassed. The update submitted at 17:09 further covered `CMPXCHG8B`. Both are under review; the permission checks require `LATX_MT=1/2` and are disabled by default.

Hanlu Li (LaurenIsACoder) [submitted](https://github.com/lat-opensource/lat/pull/472) a set of fixes for thread and seccomp resource reclamation, [AOT resource cleanup](https://github.com/lat-opensource/lat/pull/473), [unloaded library metadata reclamation](https://github.com/lat-opensource/lat/pull/475), and [self-modifying code backing store release](https://github.com/lat-opensource/lat/pull/476), reducing resource accumulation after repeated creation and unloading; she also [fixed](https://github.com/lat-opensource/lat/pull/474) a queue accounting issue when `fork` inherits deferred callbacks, as a prerequisite for library metadata reclamation. These changes are under review, and the shared-backing mode for self-modifying code remains disabled by default

Hanlu Li (LaurenIsACoder) also [submitted](https://github.com/lat-opensource/lat/pull/470) guest thread-local storage support required for native thread callbacks, establishing an independent thread context for callbacks, and on this basis [added](https://github.com/lat-opensource/lat/pull/481) a `liblat` runtime that can be embedded into LoongArch applications. Both are drafts; the former is disabled by default, and the latter depends on the former plus a separate shared library build. Additionally, during review of the futex retry patch, she [indicated](https://github.com/lat-opensource/lat/pull/461) the file mapping truncation incorrectly changing `EFAULT` to `EAGAIN`; that patch remains unmerged.

yuerengan (y347812075) [submitted](https://github.com/lat-opensource/lat/pull/466) complex address caches that reuse repeated base, index, and displacement calculations; he also [added](https://github.com/lat-opensource/lat/pull/483) a fast path for decoding common instructions based on the work of Lu Zeng (luzeng87), using direct decoding and template caching to reduce Capstone calls. Both are under review: the candidate version enables x86-64 complex-address caching and ordinary translation decoding optimizations by default, while RIP-relative caching and precache are disabled by default. The general performance benefit remains to be verified.

zqz (baibaidashixiong) [submitted](https://github.com/lat-opensource/lat/pull/477) `FUTEX_LOCK_PI2` support to prevent programs using priority-inheritance locks from terminating with `ENOSYS`, and [fixed](https://github.com/lat-opensource/lat/pull/478) KZT symbol binding mistakenly adding an addend, allowing Steam webhelper to pass the invalid bridge entry point and proceed to browser initialization; both are under review. He also [submitted](https://github.com/lat-opensource/lat/pull/485) a fix for older assembler compatibility.

yzewei [submitted](https://github.com/lat-opensource/lat/pull/469) a fix to synchronize SSE FCSR state with guest state in softfp modes, which is still a draft, covering only mode 1 and mode 2 with native x87 fast paths disabled; he also [fixed](https://github.com/lat-opensource/lat/pull/479) the JRRA fast return mistaking a guest address for host code and executing it, causing `SIGBUS`; the patch targets the already-enabled JRRA path and remains under review.

### QEMU

<!-- https://lists.gnu.org/archive/html/qemu-devel/ -->

> This section is assembled with contributions from SignKirigami, an active LoongArch contributor to QEMU.

Bibo Mao [submitted](https://lists.gnu.org/archive/html/qemu-devel/2026-09/msg01981.html) the first revision of the `CPUTimerState` structure patchset, which renames the `constant_timer_xxx` functions and `constant_timer.c` to `timer_xxx` and `timer.c` respectively, and encapsulates the CPU timer state in a `CPUTimerState` structure containing a `QEMUTimer`, IRQ number, `CPUState`, and `CPUSysState` pointers, preparing the structure to add independent guest timers later.

Bibo Mao [submitted](https://lists.gnu.org/archive/html/qemu-devel/2026-09/msg01982.html) a patch to remove the MERR CSR registers. Since neither KVM nor TCG supports MERR hardware error handling, the patch removes `CSR_MERRCTL`, `CSR_MERRINFO1`, `CSR_MERRINFO2`, `CSR_MERRENTRY`, `CSR_MERRERA`, and `CSR_MERRSAVE` from CPU initialization, the CSR information table, and the disassembler, while keeping vmstate unchanged to maintain migration compatibility.

Xianglai Li [submitted](https://lists.gnu.org/archive/html/qemu-devel/2026-09/msg01984.html) the fifth revision of the patch to fix the register residue issue during CPU reset, by clearing resettable fields in `CPULoongArchState` and `CPUSysState` with `memset()` to prevent the residual `CSR_ESTAT` interrupt state after a forced restart from leaving the VM suspended in the interrupt handling function; compared with the fourth revision, it restores `CPUSysState::end_reset_fields` to prevent `CSR_ASID`, `CSR_PRCFG1`, `CSR_PRCFG2`, and `CSR_PRCFG3` from being directly cleared to zero.

Bibo Mao [submitted](https://lists.gnu.org/archive/html/qemu-devel/2026-09/msg02377.html) a LoongArch queue pull request that includes CPU reset register cleanup, binary search by physical CPU ID for DINTC, and interrupt status display support for IPI, PCH PIC, and EXTIOI. The latter adds `InterruptStatsProvider` for irqchip in kernel, allowing `info pic` to output controller states synchronized to userspace to assist with debugging.

Bibo Mao [submitted](https://lists.gnu.org/archive/html/qemu-devel/2026-09/msg02950.html) the 2nd revision of the `CPUTimerState` structure patch series, continuing to rename the timer function and file and encapsulating a `QEMUTimer`, IRQ number, and `CPUState` for the LVZ multi-timer extension; compared with the first revision, it moves `CPUTimerState` from `CPULoongArchState` to `CPUSysState`, removes the `sys_state` pointer within it, and makes `helper_csrwr_ticlr()` use `timer->irq`.

### Issues and Requests for Assistance

> This chapter is compiled with contributions from staff of the Loongson Hobbyists' Community.

info2soft [submitted a request](https://github.com/traefik/traefik/issues/13871) for LoongArch binary releases for Traefik. The upstream noted that there had been similar requests but would like to hear from the community over the next six months to gauge interest.

### Ports, Optimizations, and Fixes

> This chapter is compiled with contributions from staff of the Loongson Hobbyists' Community.

Catty Steve (Catty2024) [submitted](https://github.com/KhronosGroup/KTX-Software/pull/1249) LoongArch and RISC-V build support to KTX-Software, a texture processing library from Khoronos. This library is an integral part of LWJGL, the Java OpenGL library used by Minecraft.

Changqi Hu [submitted](https://github.com/redis/redis/pull/15769) LoongArch hardware timer support to Redis, achieving 2.8x optimisation in specific benchmarks. He also [submitted](https://github.com/mysql/mysql-server/pull/749) a similar optimisation to MySQL.

Cheng Li (shiptux) [submitted](https://github.com/ros2/Mimick/pull/46) LoongArch64 (LP64D ABI) support to Mimick, ROS' cross-platform C mocking library.

SkyBird (skybird2333) [submitted](https://github.com/pnpm/pnpm/pull/14683) LoongArch binary build support to pnpm, as it was rewritten in Rust with v12 and, as such, could no longer be installed via npm on LoongArch.

Haiyong Sun [fixed an issue](https://gitlab.freedesktop.org/mesa/mesa/-/merge_requests/44384) where Mesa erroneously limited LoongArch's vector bitwidth to 128 bits, whereas LASX supported 256 bits. GPU drivers based on Gallium and LLVMpipe may enjoy performance uplift following this fix.
