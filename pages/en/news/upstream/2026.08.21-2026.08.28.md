This article contains LoongArch upstream community activities in the past week (as of August 28th 2026 18:00 CST), including ports, optimization, platform support, bug fixes and reports, etc. in Linux kernel, compiler toolchains, emulators and other projects.

Key highlights in this issue of upstream activities:

- Perf tool received a series of breakpoint functionality fixes
- Work to add LoongArch support to LLVM BOLT has begun; the LLVM disassembler received the initial syntax highlighting support
- Canon, a C/C++ package manager, merged the initial support for LoongArch
- Highway, a SIMD/vector library, merged the LoongArch LSX/LASX optimized implementations of `CeilInt`/`FloorInt`

## Linux Kernel

This week's activities in Linux kernel focus on fixes for current functionalities and behaviors.

### Platform Support

Two weeks ago, Huacai Chen submitted a fix for the CPU frequency/voltage scaling driver behaviour on multi-node servers. This week, he [refactored](https://lore.kernel.org/loongarch/20260828031201.1500767-1-chenhuacai@loongson.cn/) it to the second revision, fixing the wrong return value of `loongson3_cpufreq_get()` found during review of the first revision, switching to `nid_to_addrbase()` to obtain the node base address instead of hardcoding values, fixing compilation issues when `CONFIG_SMP` is disabled, correcting a series of typos, and adding `Fixes:` tags to automatically backport to active stable and longterm branches.

### KVM Subsystem

Chi Zeng [submitted](https://lore.kernel.org/loongarch/20260828093604.56622-1-zeng_chi911@163.com/) a fix for a potential kernel memory out-of-bounds read/write and data corruption in EIOINTC when it receives packets exceeding the MSI data size limit (256 bits). He also [submitted](https://lore.kernel.org/loongarch/20260828094825.357630-1-zeng_chi911@163.com/) a patch to modify KVM virtual memory slot handling, preserving architecture flags (e.g., `KVM_MEM_HUGEPAGE_CAPABLE` or `KVM_MEM_HUGEPAGE_INCAPABLE`) only when the `KVM_MR_FLAGS_ONLY` flag is set. The reason and effects of this patch remain unclear and pending review by the subsystem maintainers.

### BPF Subsystem

Kumar Kartikeya Dwivedi [submitted](https://lore.kernel.org/loongarch/a5d4c26c-6735-8af1-1d3f-fe7f1898b285@loongson.cn/) a fix for the stack parameter error in the indirect trampoline of the LoongArch BPF JIT backend. Tiezhu Yang has provided review comments, and further revisions are pending.

Tiezhu Yang [submitted](https://lore.kernel.org/loongarch/20260828075100.24776-1-yangtiezhu@loongson.cn/) a fix for the off-by-one error in the branch offset calculation logic of the `insn_is_cast_user()` function.

### Other Code Cleanups and Fixes

Wentao Guan [submitted](https://lore.kernel.org/loongarch/20260825014806.3926864-1-guanwentao@uniontech.com/) a patch to fix the LoongArch return hook trampoline code incorrectly restoring the `$r21` register used for the per-CPU base address, causing erroneous RCU warnings when using `kretprobe` under high I/O load.

Anthony Iliopoulos [submitted](https://lore.kernel.org/loongarch/20260820124933.144476-1-ailiop@suse.com/) a patch to remove the unused `setup_profiling_timer()` function from the LoongArch SMP (Symmetric Multi-Processing) code (`arch/loongarch/kernel/smp.c`), and clean up related header references.

Jérémy Jean [submitted](https://lore.kernel.org/loongarch/20260823211822.2181816-2-Jeremy.Jean@oss.cyber.gouv.fr/) a fix for kprobes not properly checking the running state, which might cause a preempt count underflow.

Fangxu Li [submitted](https://lore.kernel.org/loongarch/20260821032702.4258-1-lifangxu22@gmail.com/) a fix for the Perf tool build failure caused by the missing LoongArch Rust target platform definition (`loongarch64-unknown-linux-gnu`). Rui Wang then indicated that he had [submitted](https://lore.kernel.org/loongarch/20260414080500.320095-1-r@hev.cc/) the fix back in April with confirmations from multiple maintainers, but it remained unmerged, possibly because the upstream overlooked it.

Tiezhu Yang [submitted](https://lore.kernel.org/loongarch/20260826110306.6847-1-yangtiezhu@loongson.cn/) a series of breakpoint functionality fixes in the Perf tool.

### LLVM

<!-- lrzlin 审阅；https://github.com/llvm/llvm-project -->

CSharperMantle [added](https://github.com/llvm/llvm-project/pull/217971) the functionality to resolve symbolic operands for immediate values to the LoongArch disassembler, in preparation for subsequent BOLT-related submissions.

CSharperMantle [added](https://github.com/llvm/llvm-project/pull/218946) syntax highlighting support to the LoongArch disassembler. It does not yet distinguish between plain immediates and branch offsets.

Rui Wang [added](https://github.com/llvm/llvm-project/pull/218597) a memory barrier optimization pass that removes redundant DBARs and merges them with AMO instructions. The pass uses machine dominator and post-dominator trees to ensure the transformation is safe across basic blocks. The author also showed the changes in counts of DBAR and AMO-related static instructions when building the Clang Built Linux kernel with different configurations.

CSharperMantle [reported](https://github.com/llvm/llvm-project/issues/219224) a crash in Clang 23.1.0 when building specific C code with `-O2 -march=la664`. Subsequently, dtcxzyw's LLVM bisect infrastructure [generated](https://github.com/dtcxzyw/llvm-autoreduce/issues/360) a minimal reproducible IR and [bisected](https://github.com/dtcxzyw/llvm-bisect-service/issues/254) the issue to a previous optimization PR by Runze Lin that introduced LASX signed/zero extension patterns. Runze Lin and Opriego then independently submitted fix PRs: [#219350](https://github.com/llvm/llvm-project/pull/219350) and [#219351](https://github.com/llvm/llvm-project/pull/219351).

### Go

<!-- https://github.com/golang/go -->

A week ago, tannevaled [reported](https://github.com/golang/go/issues/81000) that in Go 1.27.0, the LoongArch `MOVD` (move doubleword) instruction generated from inlining the `QuantizeUnitToByte` function corrupted adjacent stack slots. This week, abner chenc [fixed](https://github.com/golang/go/commit/849501bbd9517ebee3423d8403c5959f21be9ed4) the problem by correcting the floating-point and integer lowering logic, ensuring both float-to-int and int-to-float conversions use floating-point registers.

## Emulators and Binary Translation

This week's activities in emulators and binary translation focus on fixes and optimizations.

### Box64

<!-- 刘阳负责；https://github.com/ptitSeb/box64 -->

Yang Liu [added](https://github.com/ksco/box64/commit/a793cd52c224fb7136438aca7e7be0c3526810e4) inter-block FLAGS dependency analysis that removes some unnecessary inter-block synchronization code for better performance. He also [fixed](https://github.com/ksco/box64/commit/2f7b82bef1ad0e5beea465733f056300fdd753fb) a regression introduced by the previous floating-point scalar register renaming optimization.

### LAT (LoongArch Architecture Translator)

<!-- https://github.com/lat-opensource/lat -->

#### Hanlu Li (LaurenIsACoder)

- [Improved](https://github.com/lat-opensource/lat/pull/421) the X11 async-handler regression test, replacing asserts that would be disabled in NDEBUG builds with always-on checks, to ensure that release builds still complete thread creation, cleanup, and callback result validations
- [Submitted](https://github.com/lat-opensource/lat/pull/428) a draft CI adjustment that restores the original GCC release jobs, reverts the full replacement of existing runners with Clang, and adds an isolated Fedora native Clang check; the PR was subsequently closed, and its three commits were taken over and merged via [PR #430](https://github.com/lat-opensource/lat/pull/430)
- [Adjusted](https://github.com/lat-opensource/lat/pull/430) the LAT CI by restoring GCC release jobs, adding an isolated Fedora native Clang check, and fixing LASX signal and pattern assembly macro parsing of ABI register aliases and the r19 mapping error, along with cleaning up Clang-exposed AOT code cache pointer types, optimizer null-pointer sentinels, and clone/fork jump context issues
- [Submitted](https://github.com/lat-opensource/lat/pull/431) a draft optimization that extends EFLAGS liveness analysis to bounded direct CALL/RET, cross-TU fixed points, and native instruction patterns. Validation showed it can reduce redundant EFLAGS code and AOT file size, but runtime movement remains sensitive to AOT code layout, so the feature is not enabled by default and this submission stays in draft status
- [Submitted](https://github.com/lat-opensource/lat/pull/433) the first draft of an experimental AOT static layout; the PR was closed and superseded by [PR #435](https://github.com/lat-opensource/lat/pull/435)
- [Resubmitted](https://github.com/lat-opensource/lat/pull/435) an experimental AOT static layout implementation that attempts to reduce instruction cache set conflicts by restricting padding based on TU control flow, loop working sets, and host L1I structure. The feature is disabled by default and test results vary across different programs, so it has not been merged as a general-purpose performance optimization

#### Lu Zeng (luzeng87)

- [Submitted](https://github.com/lat-opensource/lat/pull/432) direct translation patches for AESENC, AESENCLAST, VEX AES, and 256-bit VAES encryption rounds, while keying AOT caches by translator build identity, and fixing incomplete AES table address cache invalidation in consecutive complex memory round-key scenarios
- [Submitted](https://github.com/lat-opensource/lat/pull/437) an optimization patch that defers redundant VEX.128 YMM high-half zeroing, materializing and zeroing only when a subsequent 256-bit operation can observe the state or when the translation block is about to exit
- [Submitted](https://github.com/lat-opensource/lat/pull/438) AVX scalar physics hot-path optimizations by writing directly to the target register, reducing redundant copy/shuffle, and folding repeated scalar additions and three-way vector summation patterns. This patch depends on [PR #437](https://github.com/lat-opensource/lat/pull/437), and current performance data only covers Geekbench 7 workload 603

#### Xiaobai Wu (wojiushixiaobai)

- [Added](https://github.com/lat-opensource/lat/pull/417) a static Clang cross-compilation toolchain to the AOSC OS, Debian, and Fedora CI images; this was later reverted and re-adjusted by [PR #430](https://github.com/lat-opensource/lat/pull/430)

#### Wenqiang Wei (ganjue66da)

- [Submitted](https://github.com/lat-opensource/lat/pull/422) a strategy to skip AOT generation for low-value translation blocks, reducing generation time and cache usage. As of this issue, only build validation is available, with no runtime or cache benefit data reported yet
- [Fixed](https://github.com/lat-opensource/lat/pull/423) an issue where the i386 guest signal frame did not preserve the complete x87 state, causing stack values to be lost or restored into the wrong logical slot
- [Submitted](https://github.com/lat-opensource/lat/pull/424) a patch for siglongjmp to clean up leftover LBT TOP mappings after bypassing normal translation block epilogues, and adjusted the FCSR save ordering on syscall exit
- [Submitted](https://github.com/lat-opensource/lat/pull/425) a patch that adds checks for mixed or cross-16K guest page writes in Minke, routing such writes through the path that maintains translated code and shadow memory coherence while reducing redundant checks
- [Fixed](https://github.com/lat-opensource/lat/pull/426) optimized x87 conversions not applying the guest rounding mode to the LoongArch host FCSR, which might produce incorrect integer or floating-point conversion results
- [Submitted](https://github.com/lat-opensource/lat/pull/427) a fix for softfpu mode 2 helper regions potentially missing their epilogue at translation block boundaries, and reduced duplicate x87 state transfers for FIST, FISTP, FISTTP, FST, and FSTP within the region
- [Submitted](https://github.com/lat-opensource/lat/pull/429) a fix for LEA calculations incorrectly taking the shared memory address conversion path, erroneously adding FS/GS segment bases and corrupting the IDTest embedded resource copy
- [Submitted](https://github.com/lat-opensource/lat/pull/436) a series of patches to improve x87 state restoration across signal handling, including rebuilding the LoongArch FCSR from the restored x87 control/status word, saving and restoring LATX's private x87/MMX mode, and initializing a Linux-compatible x87 state for signal handlers. This PR depends on [PR #424](https://github.com/lat-opensource/lat/pull/424) and does not pass all tests when applied alone

#### Zewei Yang (yzewei)

- [Fixed](https://github.com/lat-opensource/lat/pull/418) softfpu XGETBV translation updating only CPUX86State but not the mapped guest EAX/EDX registers, causing subsequent guest AVX/XCR0 capability checks to read stale values

#### YueRengAn (y347812075)

- [Submitted](https://github.com/lat-opensource/lat/pull/419) a patch for Chromium/Electron's default sandbox to keep saved procfs file descriptors recognizable after entering chroot, and to hide LATX helper threads from /proc/self/task statistics, fixing ChatGPT/Chromium subprocesses triggering INT3 due to abnormal thread counts

#### zqz (baibaidashixiong)

- [Submitted](https://github.com/lat-opensource/lat/pull/420) a software-lock patch for i386 LOCK operations, to avoid unaligned LOCK instructions temporarily mremap'ing host pages after entering the LL/SC fallback, causing sporadic EFAULT in Steam's concurrent futex waits. The draft currently only covers in-process mappings and does not maintain cross-process MAP_SHARED atomicity

### QEMU

<!-- https://lists.gnu.org/archive/html/qemu-devel/ -->

Pierrick Bouvier [submitted](https://lists.gnu.org/archive/html/qemu-devel/2026-08/msg07529.html) the eighth revision of the patchset that migrates TCG tests to Meson. The patchset migrates the LoongArch64 user and system tests from the old Makefiles to Meson, and integrates them with multiarch tests and dependency management.

Song Gao [submitted](https://lists.gnu.org/archive/html/qemu-devel/2026-08/msg07119.html) a LoongArch queue pull request that merges a 1 MiB boot info memory boundary check when booting Linux directly, merges bootargs and initrd information to the device tree, and merges the fix for SWI delivery by updating the CPU hard interrupt request after modifying `CSR_ESTAT`.

Gerd Hoffmann [submitted](https://lists.gnu.org/archive/html/qemu-devel/2026-08/msg05855.html) the third revision of the EDK2 firmware update patchset. The patchset updates the EDK2 submodule, build configurations, firmware images, and ACPI test data. For LoongArch, it updates the `edk2-loongarch64` firmware and adds FPDT test baselines for the virt machine.

Yonggang Luo [submitted](https://lists.gnu.org/archive/html/qemu-devel/2026-08/msg05382.html) the first revision of the single-binary patchset. The patchset addresses symbol and QOM name collisions when linking multiple system targets into a single binary, and provides the basis for runtime emulation target selection. It renames the LoongArch virt ACPI helper with a `loongarch_virt_` prefix to avoid conflicts with identically named symbols for ARM and RISC-V.

Bibo Mao [submitted](https://lists.gnu.org/archive/html/qemu-devel/2026-08/msg07191.html) a patch to display LoongArch irqchip status, implementing `info pic` userspace diagnostic output for IPI, PCH PIC, and EXTIOI, to allow viewing and debugging register states when irqchip in the KVM kernel is enabled.

Bibo Mao [fixed](https://lists.gnu.org/archive/html/qemu-devel/2026-08/msg07195.html) a QEMU compilation failure on LoongArch hosts by changing a wrong semicolon to a comma in the `outop_revbit8` initializer.

Philippe Mathieu-Daudé [submitted](https://lists.gnu.org/archive/html/qemu-devel/2026-08/msg05112.html) the third revision of the const-correctness patchset for `SysemuCPUOps::has_work()`, adding `const` qualifiers to the CPU environment accessors and architecture-specific read-only getters. For LoongArch, `env_sys()`, `is_la64()`, `is_va32()`, and the interrupt pending checks no longer accept mutable state pointers.

Philippe Mathieu-Daudé [submitted](https://lists.gnu.org/archive/html/qemu-devel/2026-08/msg05669.html) the fourth revision of the const-correctness patchset for `SysemuCPUOps::has_work()`, extending the read-only interfaces based on the third revision. For LoongArch, it covers the CPU getters as well as the TLB/MMU getters and page table walk interfaces.

SignKirigami [submitted](https://lists.gnu.org/archive/html/qemu-devel/2026-08/msg06678.html) the fourth revision of the LoongArch virtualization extension (LVZ) TCG support patchset. It fully adds host/guest CSR and TLB banks, virtual interrupt and timer, virtual machine entry/exit and exception handling, migration state, two-stage address translation, guest CSR/TLB instructions and HVC, and fixes the address calculation for `lddir`/`ldpte`, enabling a nested KVM-accelerated virtual machine to run on a TCG-emulated LoongArch virtual machine.

### Ports, Optimizations, and Fixes

Chris-wh233 [added](https://github.com/conan-io/conan/pull/20288) LoongArch host detection and architecture configuration to Conan, a C/C++ package manager, as the first step to adding LoongArch support to this package manager. The upstream has merged this pull request.

Iacob [submitted](https://github.com/Fazecast/jSerialComm/pull/635) LoongArch JNI (Java Native Interface) support to jSerialComm, a cross-platform Java serial port communication library. The pull request is pending upstream review.

manchangfengxu [submitted](https://github.com/google/syzkaller/pull/7813) initial KVM and SYZOS support for LoongArch to syzkaller, Google's Linux kernel fuzzer. This enables automated virtual machine creation, probing, and exit tracing. The author noted that subsequent submissions will add functionalities such as extended SYZOS commands, IRQ/device debugging, multi-VCPU, and timer support. The pull request has gone through multiple AI-assisted review iterations and is pending further review from maintainers.

Ravi (RaviTriv) [added](https://github.com/google/highway/pull/3324) LSX/LASX-based `CeilInt`/`FloorInt` implementations to Highway, Google's SIMD/vector programming library. The upstream has merged the pull request.

wszqkzqk [submitted](https://github.com/sunfishcode/linux-raw-sys/pull/195) the `FIEMAP` ioctl definitions for LoongArch to linux-raw-sys, a Rust binding library for the Linux userspace API. An upstream contributor reviewed it and suggested that wszqkzqk also modify the generator code (`src/loongarch64/ioctl.rs`).

Xi Ruoyao [fixed](https://skia-review.googlesource.com/c/skcms/+/1203676) a build failure in skcms when building with GCC, caused by `[[clang::musttail]]` forcing tail calls on functions with vector parameters on platforms where the calling convention does not use vector registers for parameter passing, such as LoongArch.

Zoinen [added](https://github.com/unxed/f4/pull/669) binary build and release support for multiple architectures including LoongArch to f4, a dual-pane file manager. The upstream has merged the pull request, and the next release is expected to include LoongArch binaries. He also [added](https://github.com/unxed/vtui/pull/72) LoongArch binary build and release workflows to vtui, a Go TUI library, which has also been merged to the upstream.
